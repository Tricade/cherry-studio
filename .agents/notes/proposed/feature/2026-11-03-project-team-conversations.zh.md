# Agent Note: 项目团队会话

Status: proposed

[English](2026-11-03-project-team-conversations.md) | 中文

## 问题

本提案扩展了[私有项目工作区](2026-11-02-private-project-workspaces.md)中定义的项目会话归属规则。

Agent 可以委派任务并收到结果，但会话工具可以发现和读取调用方项目之外的会话。读取聊天记录时也没有采用委派任务的审批模式。

## 提案

使用当前交互会话协调团队。用户在启动项目会话时选择 Agent 及其配置的模型。列出当前团队成员及其模型，让协调者通过现有会话工具分配工作、核查依据并要求修改。在工具边界从数据库读取成员资格和工作区。读取、搜索或重命名会话与发送任务使用相同的审批策略。数据库确认当前项目任务正在执行时，自动审批模式下的 Agent 可读取团队会话依据。手动模式需要用户在场。交互式协调者可短暂等待自己的任务结果，在同一轮中核查依据并要求修改。异步收到结果不代表可以在无人值守时再次委派。

## 考虑过的替代方案

新增权限选择器会重复现有模式。信任模型提供的项目 ID 会允许冒充其他项目。分页后过滤或读取消息后再过滤，可能泄漏片段或遗漏有权访问的结果。

## 验收标准

- AC1 — 协调者能找到项目成员、发送任务、收到完成结果并读取该成员的项目会话。（验证：数据库集成和 MCP）
- AC2 — 直接 ID、搜索结果、元数据、工作区复用和待处理投递不会向其他项目或已移除成员开放项目聊天。个人会话仍可读取普通的非项目会话。（验证：数据库集成和 MCP）
- AC3 — Claude 和 Pi 将已有的委派审批模式用于检查会话。完全访问不能绕过项目边界，无人值守的轮次不能开始下一次委派。（验证：运行时守卫测试）
- AC4 — 项目指令与工具说明介绍如何协调和审核工作，返回结果和会话内容属于证据，而不是指令。（验证：提示词和文档）

## 风险

用户可以通过共享工作区或外部工具主动共享文件。这些规则约束 Cherry 会话工具和投递。已在授权期间投递到会话的内容会保留在历史记录中。
