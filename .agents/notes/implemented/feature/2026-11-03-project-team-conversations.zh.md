# Agent Note: 项目团队会话

Status: implemented

[English](2026-11-03-project-team-conversations.md) | 中文

## 问题

本决策扩展了[私有项目工作区](../../proposed/feature/2026-11-02-private-project-workspaces.md)中定义的项目会话归属规则。

Agent 原本可以委派任务并收到结果，但会话工具也能发现调用方项目之外的会话。读取聊天记录时没有采用委派任务的审批模式。

## 决策

使用当前交互会话协调团队。用户在启动项目会话时选择 Agent 及其配置的模型。列出当前团队成员及其模型，让协调者通过现有会话工具分配工作、核查依据并要求修改。在工具边界从数据库读取成员资格和工作区。读取、搜索或重命名会话与发送任务使用相同的审批策略。数据库确认当前项目任务正在执行时，自动审批模式下的 Agent 可读取团队会话依据。手动模式需要用户在场。交互式协调者可短暂等待自己的任务结果，在同一轮中核查依据并要求修改。异步收到结果不代表可以在无人值守时再次委派。

## 考虑过的替代方案

新增权限选择器会重复现有模式。信任模型提供的项目 ID 会允许冒充其他项目。分页后过滤或读取消息后再过滤，可能泄漏片段或遗漏有权访问的结果。

## 影响

用户可以通过共享工作区或外部工具主动共享文件。这些规则约束 Cherry 会话工具和投递。已在授权期间投递到会话的内容会保留在历史记录中。

## 验证

- AC1 — `projectTeamConversations.integration.test.ts` 通过生产环境使用的进程内 MCP 传输和已迁移的 SQLite 数据库，向另一 Agent 分配任务、等待固定的完成结果、读取指定证据并发送修改要求。测试响应覆盖投递流程，无需调用付费提供商。
- AC2 — 同一集成测试覆盖共享 Agent、个人与项目会话、两条搜索路径、已知 ID，以及派发或完成前撤销成员资格。`cherryAutonomyTools.test.ts` 验证卸载的工具输出加载过程中撤销访问权限的情况。
- AC3 — Claude 守卫和 Pi 审批测试覆盖全部权限模式。`AgentSessionRuntimeService.test.ts` 验证确切的运行中投递轮次并观察撤权。15 组受影响的本地测试通过 961 项，两个现有测试因 Windows 平台而跳过。
- AC4 — `agentPrompt.test.ts`、`ProjectsDialog.test.tsx`、翻译检查和运行时参考验证协作指引。合并后的生产构建打开独立 Windows 欢迎页面，项目端点返回 200。
