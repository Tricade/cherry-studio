# Agent Note: Dependency security remediation

Status: implemented

English | [中文](2026-11-02-security-dependency-remediation.zh.md)

## Problem

The audit of fork base `4d1af48cdb68039c67bec71a05c0ce3190b1ebde` on 2026-11-02 reports 268 advisory/version records across 55 packages: 8 critical, 102 high, 137 moderate and 21 low. These are dependency findings, not 268 demonstrated application exploits. GitHub's manifest alerts do not cover the complete pnpm 12 multi-document lockfile graph.

The installed baseline is Node 24.18.1, pnpm 12.6.0, Electron 44.9.3, React/React DOM 19.2.3 and Vitest 5.0.1. Before changing dependencies, 350 tests in 23 explicitly selected consumer files pass. Official advisories, exact published package manifests and the relevant tagged sources determine the fixed versions and API compatibility.

## Decision

Keep Node, pnpm and Electron pinned. Update vulnerable direct dependencies in every workspace manifest and resolve the lockfile with pnpm 12.6.0. Preserve the tested React/React DOM pair when resolving optional editor peers.

The CSV reader uses `parse` with its default options; the native installer uses tar `create`/streaming `extract`; ExcelJS/gaxios use UUID `v4`; ANSI rendering uses the linkify factory, `tlds` and `match`. Parent-scoped overrides retain those concrete APIs while moving to csv-parse 7.0.3, tar 7.5.21, UUID 11.1.1 and linkify-it 5.0.2. Synthetic consumer tests exercise their actual dependency resolution.

Vitest 5.0.5 requires projects in the same execution group to use the same `maxWorkers`. The `aiCore` project extends its package config rather than the root config, so it explicitly receives the shared root limit: two workers locally and 50% in CI. Its standalone package configuration stays unchanged. Separate group ordering would serialize unrelated projects without addressing the missing inheritance. The RichEditor highlighting fixture mounts the real `EditorContent` with `CodeStyleProvider`: Tiptap 3.30.5 supplies an inert React node-view placeholder until that React host mounts. A bare core `Editor` no longer represents the application's lifecycle. Sources: [Vitest 5.0.5 group ordering](https://github.com/vitest-dev/vitest/blob/v5.0.5/docs/config/sequence.md), [Tiptap 3.30.5 React node views](https://github.com/ueberdosis/tiptap/blob/v3.30.5/packages/react/src/ReactNodeViewRenderer.tsx).

The Markdown source-line fixture uses a multiline paragraph for padding so serialization tests do not start an unowned asynchronous highlight worker. Vitest's worker simulation can deliver a late response after the JSDOM environment is gone. The dedicated highlighting suite keeps real worker coverage and waits up to ten seconds for initial syntax output, matching its existing cold-start case; a one-second default timed out after reinstalling dependencies.

Zod's bundled compatibility API and Mistral's OCR operation retain targeted protections after the dependency migrations:

| Mistral SDK 2.7.0 OCR | Migrate from the standalone Zod 3 dependency to Zod 4.6.6; validate HTTP 200/422 bodies with the public early-abort API before parsing valid output; malformed output gets one diagnostic |

Replace glob 7.2.3/13.0.6 with [glob 14.0.3](https://github.com/isaacs/node-glob/tree/v14.0.3), and minimatch 3.1.5/5.1.8/9.0.7/10.2.6 with [minimatch 11.0.4](https://github.com/isaacs/minimatch/tree/v11.0.4). Exact parent-version overrides limit the migration to the inspected consumers; these are genuine published versions, not renamed backports. Node 24.18.1 satisfies both engine ranges. Remove the three obsolete glob/minimatch patch files.

Glob's Promise API replaces ASAR's callback promisification and bridges the two legacy Rimraf callback consumers. These legacy adapters retain case-sensitive matching by default on every platform and honor explicit `nocase`. ASAR resolves its input directory and defaults the glob working directory to that source so relative ignore patterns remain effective when packaging a directory outside the process working directory. Keep explicit caller working directories. Preserve native Windows pattern separators, archive ordering, unpack filters, directory-link descendant filtering and prefix siblings. Rimraf recognizes brace-only patterns before asynchronous and synchronous cleanup. ASAR and archive expansion adapters normalize native Windows separators before brace expansion, preserve sorting and `nonull` alternatives, and keep ignored paths and subtrees excluded from fallback results. Archive expansion adapters use an explicit minimatch dependency supplied through package extensions. Other obsolete Glob 7 options are not advertised as a general compatibility API.

Minimatch 11 replaces regex construction with its matcher API. Patch both module formats of ESLint's legacy config loader and import-boundary rule, plus ASAR, directory comparison and ESLint's legacy file enumerator. The ESM entry of `@eslint/config-array` 0.21.2 imports named `Minimatch`; its CommonJS entry already uses that API. Retain the Windows separator policy only for former Minimatch 3 consumers; installed Minimatch 5.1.8 already has the newer escaping default. Modern consumers keep their named APIs. App-builder's directory matching uses the retained `match(path, partial)` and treats any non-string set entry as magic, which also supports Minimatch 11's Matcher objects. Keep version-specific patch and override review in Dependabot.

The [Glob 14 changelog](https://github.com/isaacs/node-glob/blob/v14.0.3/changelog.md) documents changed rooted-ignore and matching edge cases. Fixtures exercise the actual consumer APIs and their used options; they do not promise every historical Glob 7 option. pnpm also deduplicates the root htmlparser2 resolution from 10.0.0 to the already installed [10.1.0](https://github.com/fb55/htmlparser2/releases/tag/v10.1.0) family used by html-to-text; its public parser APIs remain unchanged and the release updates entity decoding. The CI platform jobs explicitly run the dependency glob compatibility and security suites on Windows and macOS, alongside the existing platform tests.

Remove every deepmerge 4.3.1 path rather than retaining its backport. [html-to-text 10.0.1](https://github.com/html-to-text/node-html-to-text/blob/1c39d9885075836a7e45d0236c7a5541dede8e52/packages/html-to-text/CHANGELOG.md) uses deepmerge-ts 8 (resolved to 8.0.2) and supports the repository's Node runtime. Keep the existing speech selectors and formatters. The SVG generator calls its existing SVGO 3.3.5 optimizer and SVGR 8.1.0 JSX plugin directly, then [Prettier 3.8.1's asynchronous formatter](https://github.com/prettier/prettier/blob/3.8.1/website/versioned_docs/version-stable/api.md). This replaces two wrappers that still depend on deepmerge. Preserve the explicit optimization/formatting options, embedded-HTML removal, viewBox/path data and per-instance React IDs. Remove the unused deepmerge patch and Dependabot group exclusion.

The UI package's existing standalone type check also fails on its Markdown CSS import with the baseline generator. Its root command resolves TypeScript 7.0.2, whose [side-effect import check defaults to true](https://github.com/microsoft/TypeScript/blob/v7.0.2/src/compiler/commandLineParser.ts). Declare CSS asset imports in the UI package's existing `src/types` directory instead of disabling that check or changing the compiler. This is a type-only declaration, not a CSS loader or a runtime change.

## Alternatives considered

- Merging only the four initial Dependabot PRs leaves vulnerable root and transitive copies.
- Forcing every dependency to its newest major bypasses declared APIs and discards app patches.
- Merely overriding Mistral 1.11.0 to Zod 4 leaves its `zod/v3` parser usage. Mistral 2.7.0 actually uses `zod/v4`; its narrower upgrade preserves the used OCR/file APIs without moving to SDK 3.5.0. Its declared Zod range also permits v3, so a parent-scoped override selects 4.6.6. Zod 4's bundled v3 compatibility parser still needs its backport.
- Ignoring advisories or rewriting pnpm's lockfile for a scanner would not repair runtime behavior.

## Consequences

After all three migrations, `pnpm audit --json` exits 0 with zero advisories. The resolved application graph no longer contains standalone Zod 3.25.76, deepmerge 4.3.1, its two SVGR wrappers or the old glob/minimatch versions. No advisory is suppressed. This package audit does not establish absence of application vulnerabilities; complete GitHub indexing and the live alert state still require separate readback after merge.

**Zod 3 dependency removed, bundled compatibility protection retained:** the Mistral 1.11.0 → Zod 3.25.76 path reported by [GHSA-mrhx-c7xc-m3w5](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5) is replaced by Mistral 2.7.0 → Zod 4.6.6. Before the original backport, a 10,000-element invalid constrained array produced 10,001 issues through both Zod 3.25.76 and Zod 4.6.6's `/v3` path; patched Zod 4's root produced one. The [official fix](https://github.com/colinhacks/zod/commit/a0ebf970f2d752e5f58527cd2942ff48be4f46bd) changes v4 only, and the [v3 follow-up](https://github.com/colinhacks/zod/issues/6653) does not provide a published fixed v3 release. The remaining compatibility parser keeps its tested early rejection; the unused standalone-package patch is removed.

Arrays exceeding `.max()` or `.length()`, and sets exceeding `.max()` or `.size()`, retain their existing size issues and stop before element parsing or enclosing refinements, synchronously and asynchronously. Overlapping array bounds retain both size diagnostics. Valid values at the bound, lower-bound-only and unbounded collections, transforms and valid union alternatives keep their behavior. Zod 3 maps have no size-bound API. These patches do not impose a global issue budget or raw-body limit; callers still need bounds for untrusted collections.

Cherry's image/document processors call `ocr.process` against a configured endpoint. A malicious or compromised endpoint could return thousands of malformed pages/images and cause an issue-object allocation for each item. [Zod 4.6.6's public `validate`](https://github.com/colinhacks/zod/blob/v4.6.6/packages/zod/src/v4/core/parse.ts) stops at the first invalid item; its ordinary error callback runs only after raw issues have accumulated and cannot implement the old ErrorMap budget. The [SDK 2.7.0 OCR operation](https://github.com/mistralai/client-ts/blob/v2.7.0/src/funcs/ocrProcess.ts) therefore checks validity first, throws a one-issue ZodError on failure, and parses valid responses normally to preserve field transformations. Valid output is traversed twice and has no added page or byte limit. Other SDK matchers remain unchanged.

Malformed HTTP 200/422 output now produces ResponseValidationError with one generic diagnostic instead of up to 100 detailed diagnostics. A valid structured HTTP 422 body still produces HTTPValidationError with its API details. This is an accepted error-reporting tradeoff. This mitigation bounds diagnostic amplification, not the raw HTTP body size. New SDK operations or direct serialization-helper consumers still need their own validation review.

Source evidence for backports: [Glob advisory](https://github.com/isaacs/node-glob/security/advisories/GHSA-3g3m-2fjr-6pw4), [Minimatch fix](https://github.com/isaacs/minimatch/commit/77a0f5c4b80bdc641c3c930a1d9edf5ad2db57f8), [Deepmerge advisory](https://github.com/advisories/GHSA-gcqx-w48m-w2h4). OfficeParser's [6.1.0 documentation](https://github.com/harshankur/officeParser/blob/v6.1.0/README.md) and stream-json's [3.x migration guide](https://github.com/uhop/stream-json/wiki/Migrating-from-2.x-to-3.x) explain the explicit consumer migrations.

The existing docs impact candidates describe unchanged architecture, migration format, provider contracts and release operations; they need no semantic rewrite. No installer or release is produced. Packaged application behavior and macOS/Linux execution require separate verification.
