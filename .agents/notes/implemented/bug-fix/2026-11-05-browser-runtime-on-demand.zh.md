# Agent Note: 按需启用浏览器 Runtime

Status: implemented

[English](2026-11-05-browser-runtime-on-demand.md) | 中文

## 问题

常规网页快照或操作在连接调试器时启用 V8 Runtime 事件上报。有些网页会对控制台格式化带来的副作用作出反应，即使该操作并不使用这些事件。

## 决策

浏览器在检查控制台、捕获标注或发现 WebMCP 工具时启用 Runtime。同一次调试器连接内，并发调用共享启用操作，各等待方保留自己的截止时间和取消控制。启用失败后可以重试，断开时重置订阅状态。

此修复移植了[上游浏览器修复](https://github.com/CherryHQ/cherry-studio/commit/1a0530f068043158379322f1e7c8f32f692b0aca)，保留分支的 URL 脱敏，并记录 Chromium 重放缓冲控制台消息的行为。

## 备选方案

提前启用会向所有操作提供 Runtime 事件，包括从不使用这些事件的操作。每个工具结束后关闭 Runtime 会破坏控制台的连续记录，以及标注和 WebMCP 所依赖的上下文生命周期。

## 影响

常规网页快照和输入操作不订阅 Runtime。读取控制台时标明本次调用是否开启订阅。第一次读取可能包含 Chromium 仍缓冲的早期消息，订阅前的历史取决于目标。网络捕获、快照 URL 脱敏和浏览器权限保持原有行为。

## 验证

- Regression — 七组主进程定向测试共通过 184 个用例，覆盖常规调试器连接、并发与取消读取、失败重试、重新连接、标注上下文生命周期、WebMCP 和 URL 脱敏。
- Regression — 使用 Chromium 152.0.7977.167 的独立 Electron 44.9.3 协议探针验证启用 Runtime 前可捕获无障碍树和执行输入。启用时会重放缓冲消息，之后能收到实时控制台事件并调用隔离环境绑定。
