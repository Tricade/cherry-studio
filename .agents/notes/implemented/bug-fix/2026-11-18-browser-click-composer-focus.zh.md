# Agent Note: 浏览器工具点击后恢复输入框焦点

Status: implemented

[English](2026-11-18-browser-click-composer-focus.md) | 中文

## 问题

用户编辑聊天草稿时，浏览器工具的点击可能会将焦点移到内嵌网页。在 Electron 44.9.3 中，真实点击网页按钮或文本框会将焦点从宿主输入框移到 webview。

## 决策

主进程在向借用的网页发送点击前，请求其所属渲染进程记住当前文本输入控件。鼠标事件发送结束后（包括出错的情况），如果焦点被该 webview 取得，且原控件仍在页面上并可交互，渲染进程就恢复焦点。如果宿主中的焦点移到了其他控件，就丢弃已记录的控件。每个请求都与会话、网页和本次点击绑定。

## 考虑过的方案

- 在 Electron 44.9.3 中，通过网页的 `webContents.sendInputEvent` 发送鼠标事件也会把焦点移到 webview。
- 用 DOM `click()` 取代真实点击会改变网页的焦点和鼠标事件行为，包括非主键和多次点击。

## 影响

焦点在鼠标事件发送结束时恢复。渲染进程仅在本次点击期间在本地保留记录的 DOM 控件。手动浏览和独立浏览器标签页维持原有焦点行为。

## 验证

- Regression — `useAgentBrowserGuest.test.ts`: 与点击匹配的请求会恢复草稿和选区，过时的请求或期间发生的焦点变化会保留当前焦点。
- Regression — `actions.test.ts`: 即使按下鼠标的操作失败，也会恢复原文本输入控件的焦点。
- Regression — `Electron 44.9.3 / Chromium 152.0.7977.167`: 隔离的 Agent 和话题网页执行浏览器工具点击后，文本区和富文本输入框保留选区，网页仍能处理 Unicode 文本、退格键和滚动。
