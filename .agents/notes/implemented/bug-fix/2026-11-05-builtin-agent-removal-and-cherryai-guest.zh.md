# Agent Note: 内置智能体移除与 CherryAI 访客推理

Status: implemented

[English](2026-11-05-builtin-agent-removal-and-cherryai-guest.md) | 中文

## Problem

Cherry Assistant 和 Cherry Support 的普通智能体菜单只允许归档会话。记录消失后，启动种子或专用入口可能重新创建智能体。此外，即使用户的对话使用其他服务，自动命名仍可能使用预置的 CherryAI 访客模型或回退到该模型。访客传输验证应用身份，无需个人 Cherry 账号。

## Decision

两个智能体使用普通的归档、恢复和永久删除操作。移除标记与删除在同一个数据库事务中写入，种子和内置会话入口均遵守该标记。显式恢复会清除标记。隐藏的 Doctor 角色和现有工具保护保持各自的契约。

自动摘要只使用可用的已配置快速模型或默认模型，否则保留由首条消息在本地生成的标题。自动对话命名从不使用访客模型。访客传输在签名和发送前必须得到用户显式启用。模型设置说明传输目的地和数据。

## Alternatives considered

- 仅在渲染进程隐藏智能体：种子和专用会话入口仍可能重新创建。
- 只保留归档记录：清空归档会丢失删除信息。
- 只在模型选择器限制访客请求：已保存的选择和聊天之外的调用方可以绕过。
- 修改所有 Cherry 连接：需要账号的 Cherry Cloud 和经过确认的诊断上传是独立流程。

## Consequences

不需要新的 SQLite 架构或旧版迁移。依赖访客模型的用户必须显式启用或选择其他模型。关闭后会限制后续请求，不会取消已经发送的请求。

## Verification

- 回归验证 — `builtinAgentDeletion.test.ts` 在真实 SQLite 测试数据库中覆盖两个角色、关联会话、种子重跑、显式恢复和永久删除。
- 回归验证 — `TopicNamingService.test.ts` 和服务商的 `config.test.ts` 复现意外回退，验证本地标题以及使用网络替身的访客传输。Cherry Cloud 测试覆盖其独立传输。
- 回归验证 — 智能体和设置渲染测试覆盖归档、保留会话、初始设置以及显式启用。隔离的 Electron 配置验证两个智能体可通过菜单从活动列表移除、专用入口遵守移除状态，以及访客开关初始关闭并显示目的地。验证未向真实服务发送推理请求。
